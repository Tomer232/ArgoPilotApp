## Findings

### QA-1 The overview says "0 of N plots need water today" when it has no plans (high, UX)

**Status: fixed** (DECISIONS O105): the headline now adds "4 plots have no plan right now: weather-service is not reachable." (checked with weather down and with the planner down).

- **Steps:**
  ```bash
  bash .claude/skills/run-stack/scripts/stack.sh stop planner     # or: stop weather
  curl -s localhost:3000/ | grep -o '[0-9]* of [0-9]* plots need water today[^<]*'
  bash .claude/skills/run-stack/scripts/stack.sh restart planner
  ```
- **Expected:** when a plan could not be calculated, the page doesn't claim an answer for that plot. FR-2.14 ("Never a plan of zeros"), FR-2.18 (the user sees what happened).
- **Actual:** `0 of 7 plots need water today, with the default choices.` above seven rows that each say `Plan unavailable`. The same happens with weather down, and with a stale cache for only some cells: then only the cached plots get an answer, and the count still reads as if it covers all seven.
- **Notes:** `src/app/page.tsx` counts only plans that came back `ok`, and the subtitle doesn't mention the plots it couldn't count. The headline is the first thing a grower reads, and it reads as "nothing to do today".

### QA-2 "Infinity h NaN min" when the drip rate rounds to 0 (high, UI)

**Status: fixed** (DECISIONS O106): the card says "Drip rate under 0.01 mm/h" and leaves out the refill time; no "Infinity" or "NaN" in the page.

- **Steps:**
  ```bash
  curl -s -X POST localhost:8000/v1/plots -H 'Content-Type: application/json' -d '{"farm_id":"b7e2c0a0-3c1d-4f0a-9a11-0c5d2e6f1001","name":"QA wide drip","area_m2":1000,"crop_id":"tomato","planting_date":"2026-11-18","soil_id":"sand","row_spacing_m":50,"emitter_spacing_m":50,"emitter_id":"dripnet-pc-0.6","lat":31.25,"lon":34.79}'
  # open http://localhost:3000/plots/<id>?start_pct=0
  ```
- **Expected:** no impossible number on screen (severity rule; FR-2.16 "big and clear").
- **Actual:** `Drip rate 0 mm/h · refill from 50 % to full Infinity h NaN min`. The planner sends `"drip_mm_per_hour": 0.0` (0.6 L/h over 2,500 m² is 0.00024 mm/h, rounded to 2 decimals), and `refillMinutes` in `today-recommendation.tsx` divides by it. The same page says `Water for 24 h, 576,000 L on the plot (0.01 mm of water)`.
- **Notes:** the registry accepts 50 m spacing, so this is valid data. Any plot with flow / (row x emitter spacing) under 0.005 mm/h triggers it.

### QA-3 A long plot name very likely makes the plot page scroll sideways at 375 px (high, NFR) - needs a browser check

**Status: fixed** (DECISIONS O107): confirmed first in a headless Chromium at 375 px (546 px and 1360 px wide before the fix), then 375 px on every page after it, with long names wrapping; North block stays on one line.

- **Steps:**
  ```bash
  curl -s -X POST localhost:8000/v1/plots -H 'Content-Type: application/json' -d '{"farm_id":"b7e2c0a0-3c1d-4f0a-9a11-0c5d2e6f1001","name":"Northern greenhouse tomatoes, row 4","area_m2":1000,"crop_id":"tomato","planting_date":"2026-10-01","soil_id":"loam","row_spacing_m":1.5,"emitter_spacing_m":0.4,"emitter_id":"dripnet-pc-1.0","lat":31.25,"lon":34.79}'
  # open http://localhost:3000/plots/<id> at 375 px wide (DevTools device toolbar)
  ```
- **Expected:** NFR-2.8, no horizontal scrolling at 375 px. Plot names may be up to 200 characters (registry).
- **Actual (from the code, not seen in a browser):** the plot name is the `PlotSwitcher` trigger, which the shadcn `SelectTrigger` sets to `w-fit whitespace-nowrap` at `text-[28px]`. Nothing in `src/` sets `overflow-wrap`, `break-words` or `truncate`, and no parent clips the overflow. A 35-character name at 28 px is about 490 px wide. The same goes for a long unbroken word in the overview rows, the farm card titles and the `/farms` and `/plots` tables (tested with a 170-character name: it renders, and nothing in the markup lets it wrap).
- **Notes:** the demo names are all short, so the O104 check at 375 px wouldn't have caught this.

## Tried and held

- API (as the frontend uses it): unknown plot id, non-UUID id, the all-zero UUID, `/plots/{id}/extra` and `..%2F` paths all give a real 404 and the "Plot not found" page. An uppercase UUID opens the plot. Repeated `start_pct` uses the first value. Unknown query parameters (`foo=bar`) and `view=xyz` are ignored, and `start_pct=1e2` is read as 100.
- Between services: with planner, weather or registry stopped, every page answers 200 with the shell. The plot page names the service (`planner-service is not reachable.`, `weather-service is not reachable.`, `registry-service is not reachable.`), the status card marks the right one down, and the registry list pages say `The plots can't be loaded right now`. All pages recovered after `restart`.
- Stale forecast: today's card shows `Stale forecast` and the time of the forecast; every table row and the timeline window carry the label (FR-2.13, FR-2.17).
- Hand check (irrigation-calc-reference) for North block, `start_pct=45`: TAW 175 x 0.7 = 122.5, drip 1.0/(1.5 x 0.4) = 1.67 mm/h, cap 40 mm, Dr_end 67.38 + 2.21 = 69.58, so the level is 52.92 (below the 61.25 trigger), the day is capped at 40 mm, the bucket ends at 92.92, litres 40,000 and run time 1440 min. Planner and page match.
- Security: `<script>alert(1)</script>`, `<img src=x onerror=...>` and `"quoted"` in farm and plot names are escaped on `/`, `/farms`, `/plots` and the plot page (no raw tag in the HTML).
- Extreme valid plots (0.01 m^2 with 200 mm/h drip; 100,000,000 m^2) render without a crash.
- `start=25:99` gives the A63 note and falls back to 06:00.
- Load times on the QA stack: 0.1 to 0.6 s per page.
